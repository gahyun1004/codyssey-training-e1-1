# Codex 공통 수용 기준

이 문서는 작업별 명세에 별도 규정이 없을 때 적용하는 공통 완료 기준입니다. 루트 `AGENTS.md`와 적용되는 하위 `AGENTS.md`를 함께 따릅니다.

## 1. 요구사항 충족

- 요청된 동작 또는 문서 변경이 구현되어야 합니다.
- 작업 명세의 필수 요구사항을 항목별로 확인할 수 있어야 합니다.
- 작업 범위를 임의로 확장하지 않아야 합니다.
- 부분 구현이라면 완료로 표현하지 말고 남은 범위와 이유를 보고해야 합니다.

## 2. 저장소 일관성

- 명령, 파일 경로, 스크립트 이름과 문서 설명이 일치해야 합니다.
- 파일을 추가·이동·삭제했다면 `docs/repository-structure.md`가 갱신되어야 합니다.
- 사용자 실행 흐름이 바뀌었다면 README, 플랫폼 문서, VS Code Task와 CI 중 영향받는 항목이 동기화되어야 합니다.
- 중복되거나 상충하는 새로운 기준 문서를 만들지 않아야 합니다.

## 3. 증거 무결성

- 실행하지 않은 명령 결과를 작성하지 않아야 합니다.
- 가상의 로그, 스크린샷, 버전, 날짜, 경로, commit SHA와 성공 결과가 없어야 합니다.
- 실제 증거를 확인하지 않고 `docs/evidence-index.md`를 `완료`로 변경하지 않아야 합니다.
- CI 결과를 개인 장비 증거로 표현하지 않아야 합니다.
- 예시는 예시로 명확하게 표시되어야 합니다.

## 4. 보안과 개인정보

- 토큰, 비밀번호, 인증 코드, 개인키와 credential URL이 없어야 합니다.
- 불필요한 사용자 홈 경로, 사용자 이름, 이메일과 내부 호스트 정보가 마스킹되어야 합니다.
- 기존 마스킹·secret 검사·최소 권한 설정을 약화하지 않아야 합니다.
- 파괴적 명령이 새로 추가되지 않아야 합니다. 필요한 경우 명시적 사용자 승인과 안전장치가 있어야 합니다.

## 5. 플랫폼 정확성

- Windows/WSL과 macOS/OrbStack 절차가 혼합되지 않아야 합니다.
- 공통 명령은 두 Ubuntu 환경에서 실제로 공통 사용 가능한 경우에만 공통 위치에 있어야 합니다.
- 사용하지 않은 플랫폼의 증거는 `해당 없음`으로 처리해야 합니다.
- Docker Desktop WSL Integration과 WSL 내부 Docker Engine을 동시에 요구하지 않아야 합니다.

## 6. 코드와 스크립트 품질

### Bash

- 구문 오류가 없어야 합니다.
- ShellCheck warning 이상에서 문제가 없어야 합니다.
- 변수와 경로가 적절히 인용되어야 합니다.
- 필수 검증 실패 시 nonzero로 종료해야 합니다.
- 증거 수집 스크립트가 완료 상태를 자동 조작하지 않아야 합니다.

### PowerShell

- PowerShell parser를 통과해야 합니다.
- PSScriptAnalyzer Error가 없어야 합니다.
- strict mode와 오류 처리 정책이 유지되어야 합니다.
- 경로 및 WSL 배포판을 파괴적으로 처리하지 않아야 합니다.

### Docker

- Dockerfile 변경 시 base image pinning 정책이 유지되어야 합니다.
- build가 성공해야 합니다.
- 웹 서비스 변경 시 HTTP smoke test가 성공해야 합니다.
- 테스트 컨테이너가 정리되어야 합니다.

## 7. 문서 품질

- Markdown 상대 링크가 유효해야 합니다.
- 결과와 절차가 구분되어야 합니다.
- 빈 템플릿 필드를 추측으로 채우지 않아야 합니다.
- README는 중앙 수행 흐름, 플랫폼 문서는 상세 절차, Codex 문서는 작업 규칙이라는 역할 분리가 유지되어야 합니다.
- 설명, 작업 원칙, 수용 기준과 완료 보고는 기본적으로 한국어로 작성되어야 합니다.
- 파일명, 경로, 명령어, 코드, 옵션과 공식 제품·도구 명칭은 원문 표기를 유지해야 합니다.
- 번역으로 인해 기술 식별자나 명령의 의미가 바뀌지 않아야 합니다.

## 8. 검증과 보고

최소한 다음 검증을 실행해야 합니다.

```bash
bash scripts/ubuntu/validate-repository.sh
```

작업 영향에 따라 ShellCheck, PowerShell 검사, Docker build와 smoke test를 추가합니다.

완료 보고에는 다음이 있어야 합니다.

- 변경 파일과 변경 이유
- 실제로 실행한 검증 명령
- 검증 결과
- 실행하지 못한 검증과 이유
- 실제 장비에서 남은 작업
- 증거 및 개인정보 검토 결과
- 알려진 위험과 후속 작업

## 9. 완료 판정

다음 중 하나라도 해당하면 작업은 완전한 완료가 아닙니다.

- 필수 수용 기준이 충족되지 않음
- 필수 검증이 실패함
- 검증 결과가 불명확함
- 실제 수행하지 않은 결과가 포함됨
- 민감정보 노출 가능성이 남아 있음
- 문서와 구현이 서로 다름

이 경우 상태를 `부분 완료`, `차단됨` 또는 `보류`로 명확하게 보고합니다.
