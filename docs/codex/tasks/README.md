# Codex 작업 명세

이 디렉터리에는 실제 Codex 작업별 명세를 저장합니다. 작업 명세는 구현 지시서이며 미션 수행 증거가 아닙니다.

## 파일 이름

설명 가능한 kebab-case 파일명을 사용합니다.

```text
improve-wsl-evidence.md
update-docker-validation.md
reorganize-platform-docs.md
```

`task-1.md`, `new.md`, `final-final.md`처럼 의미가 불분명한 이름은 피합니다.

## 작성 방법

1. 상위 [`TASK_TEMPLATE.md`](../TASK_TEMPLATE.md)를 복사합니다.
2. 목적, 허용 범위, 금지 범위와 수용 기준을 구체적으로 작성합니다.
3. 실제 장비에서만 가능한 항목을 분리합니다.
4. 필요한 검증 명령을 명시합니다.
5. 작업 종료 후 상태와 관련 PR을 갱신합니다.

## Codex 지시 예시

```text
AGENTS.md와 docs/codex/tasks/<작업명>.md를 먼저 읽으세요.
적용되는 하위 AGENTS.md를 준수하고 허용 범위 안에서만 수정하세요.
검증을 실제로 실행한 뒤 CHANGE_REPORT_TEMPLATE 형식으로 보고하세요.
실행하지 못한 검증과 실제 장비에서 남은 작업을 숨기지 마세요.
```

## 상태 관리

- `초안`: 요구사항이 확정되지 않음
- `진행 중`: 작업이 시작됨
- `완료`: 수용 기준을 충족하고 검증 결과가 보고됨
- `보류`: 차단 요인 또는 우선순위 변경으로 중단됨

작업 명세의 `완료`는 코드·문서 작업 완료를 뜻합니다. 개인 장비 증거까지 자동으로 완료되었다는 의미가 아닙니다.

## 충돌 방지

- 하나의 활성 작업에 하나의 기준 명세를 둡니다.
- 현재 구현과 충돌하는 오래된 명세는 상태를 표시하거나 별도 보관합니다.
- 공통 규칙은 작업마다 복사하지 말고 `AGENTS.md`와 `ACCEPTANCE_CRITERIA.md`를 참조합니다.
- 실제 로그·스크린샷·증거 파일을 작업 명세에 직접 포함하지 않습니다.
